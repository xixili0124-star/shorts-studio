# 숏츠 스튜디오

**https://shorts-studio-75p.pages.dev**

세로 영상(9:16) 숏츠·릴스를 **브라우저 안에서만** 만드는 웹 편집기입니다.
영상·이미지·음악 파일이 서버로 전송되지 않고, 인코딩까지 전부 사용자 PC에서 처리합니다.
[썸네일 스튜디오](../naver-thumbnail-studio)와 같은 구조(빌드 없는 정적 사이트 + Cloudflare Pages)입니다.

## 기능

- **혼합 타임라인** — 영상 클립과 이미지 클립을 순서대로 배치 (순서 바꾸기·삭제)
- **9:16 리프레임** — 꽉 채우기/전체 보이기, 캔버스 드래그로 위치 조정, 휠로 확대, 여백은 흐린 원본/단색
- **트림** — 시작·끝 지점 지정 (재생 위치를 그대로 트림 지점으로 찍는 [현재] 버튼)
- **이미지 클립** — 표시 시간 조절 + 켄번즈(천천히 확대/축소/좌우 팬)
- **텍스트 오버레이** — 한글 폰트 8종, 외곽선·배경박스, 구간 지정, 등장 효과(페이드/올라오기/팝)
- **자막** — 구간별 직접 입력, SRT/VTT 가져오기·내보내기, 스타일 일괄 지정
- **타임라인에서 바로 조정** — 자막·텍스트 블록의 양 끝을 끌면 시작·끝 지점이,
  가운데를 끌면 길이를 유지한 채 위치가 바뀐다
- **오디오** — 클립별 볼륨·음소거, 배경음악 추가(볼륨·시작지점·페이드·반복), 클립 페이드와 연동
- **내보내기** — 1080×1920 / 720×1280 / 1440×2560, 24·30·60fps, MP4(H.264+AAC)
  - 소리가 없어도 무음 AAC 트랙을 넣습니다. 트랙이 아예 없으면 인스타 릴스 처리가 실패합니다.
  - moov 를 파일 앞으로(faststart) 보냅니다. 뒤에 있으면 릴스 컨테이너가 ERROR 로 떨어집니다.
- **템플릿(밴드 레이아웃)** — 상단 훅 문구 + 가운데 영상 띠 + 하단 댓글 카드 구성.
  한국 숏츠에서 흔한 반응형 포맷을 한 번에 잡아준다
- **자동 자막** — 말소리를 알아듣고 자막을 자동으로 채움 (Cloudflare Workers AI · Whisper)
- **유튜브 숏츠 바로 업로드** — 편집기에서 구글 계정 연결 후 업로드 (아래 주의사항 참고)
- 안전영역 가이드 (플랫폼 UI에 가려지는 영역 표시)

## 어떻게 동작하나

미리보기와 내보내기가 **같은 렌더러**(`js/render.js`)를 씁니다. 화면에서 본 것이 그대로 파일로 나옵니다.

| | 미리보기 | 내보내기 |
|---|---|---|
| 프레임 소스 | `<video>` 엘리먼트 | mediabunny `VideoSampleSink` (프레임 단위 정확) |
| 구동 | requestAnimationFrame (실시간) | 프레임 루프 (실시간보다 빠름) |
| 오디오 | video/audio 엘리먼트 | OfflineAudioContext 로 믹싱 후 AAC 인코딩 |

인코딩은 [mediabunny](https://mediabunny.dev) 1.55.1 (WebCodecs 래퍼)를 씁니다.
CDN 의존을 없애려고 `public/vendor/mediabunny.min.js` 로 넣어뒀습니다.

**브라우저 지원**: 크롬·엣지 권장(하드웨어 인코딩). WebCodecs 인코딩이 없는 브라우저에서는
MediaRecorder 실시간 녹화(WebM)로 자동 전환되며, 헤더의 배지에 현재 방식이 표시됩니다.

### 파일 불러오기 2단계

영상은 먼저 브라우저 기본 재생기(`<video>`)로 열어 보고, 실패하면 **디코더 모드**로 다시 시도합니다.
MPEG-TS 처럼 브라우저가 컨테이너를 모르는 파일, 인덱스(moov)가 끝에 있는 초대형 MP4 등이 여기서 살아납니다.
디코더 모드에서는 미리보기 소리가 나오지 않지만(완성본에는 정상적으로 들어감) 편집·내보내기는 동일합니다.
그마저도 안 되면 **코덱 이름을 찍어서** 왜 안 되는지 알려줍니다.

## 템플릿 (밴드 레이아웃)

[템플릿] 탭에서 형식을 **상단문구 + 영상밴드 + 댓글** 로 바꾸면 구성이 이렇게 된다.

```
+------------------+
|  훅 문구 (강조색)   |  hook   — 별표로 감싼 조각만 강조색
+------------------+
|                  |
|   영상 (가운데 띠)   |  videoTop / videoHeight 로 위치·높이 조절
|                  |
+------------------+
|   댓글 카드         |  comment — 이름/내용/좋아요/시간
+------------------+
```

훅 문구는 `교도소 아버지와 *절연한 이유*` 처럼 **별표로 감싼 부분만 강조색**으로 칠한다.
한 줄 안에서 색이 바뀌므로 조각별 폭을 재서 가운데 정렬을 직접 계산한다 (`drawHook`).

영상은 밴드 사각형으로 클리핑해서 그린다. 밴드를 켜면 클립의 `contain` 은 `cover` 로 바꾼다 —
띠 안에서 또 여백이 생기면 이상해서다.

댓글 카드는 **특정 플랫폼 UI 를 그대로 베끼지 않는다.** 아바타(이름 첫 글자) + 이름 + 내용 +
좋아요 정도만 있는 일반적인 모양으로 그린다.

## 자동 자막

[자막] 탭의 **자동 자막 만들기** 를 누르면 영상 속 말소리를 알아듣고 자막을 채운다.
14초 영상 기준 4초쯤 걸린다.

- 배경음악은 빼고 보낸다. 노래가 섞이면 알아듣는 정확도가 떨어진다.
- 음소거한 클립은 인식 대상에서 빠진다.
- 결과는 그냥 자막 목록이라, 틀린 부분은 손으로 고치거나 SRT 로 빼서 고칠 수 있다.

### 말이 흐려지는 구간

웅얼거리거나 소리가 작아지면 Whisper 는 **틀리게 받아쓰는 게 아니라 그 구간을 통째로 버린다.**
자막이 어색해지는 게 아니라 아예 없어지는 것이라, 눈으로는 안 보이고 다 들어봐야 알 수 있다.
(VAD 를 꺼도, 문턱값을 낮춰도 안 살아난다. 모델이 정말 못 알아듣는 것이다.)

그래서 두 가지를 표시해 준다.

| 표시 | 뜻 |
|---|---|
| 타임라인의 빗금 블록 | 소리는 나는데 자막이 없는 구간. 눌러서 그 지점으로 이동 |
| 자막 목록의 `확인` 배지 | 모델이 알아듣기 애매해한 구간 (신뢰도 0.5 미만) |

빈 구간은 `findUncaptioned()` 가 오디오 RMS 로 찾는다. 문턱값을 피크 기준으로 잡으면 안 된다 —
웅얼거린 말은 또렷한 말보다 10배쯤 작아서, "피크의 몇 %" 로 자르면 정작 찾아야 할 구간이
묵음 처리된다. 무음 바닥에서 살짝 올린 절대값(-48dBFS)을 쓰되 시끄러운 녹음에서는 바닥을 따라 올린다.

### 서버 (stt-worker/)

정적 사이트는 API 키를 숨길 수 없어서 음성 인식을 직접 못 부른다.
`stt-worker/` 가 그 사이에 서서 Cloudflare Workers AI 의 Whisper 를 대신 호출한다.
AI 바인딩을 쓰므로 코드에 넣을 키가 없다.

```bash
cd stt-worker && npx wrangler deploy
```

주소는 https://shorts-studio-stt.xixili0124.workers.dev 이고,
클라이언트 쪽 주소는 `public/js/transcribe.js` 의 `ENDPOINT` 에 있다.
CORS 는 배포 주소와 localhost 만 허용한다 (`stt-worker/src/index.js` 의 `ALLOWED_ORIGINS`).

**비용**: `@cf/openai/whisper-large-v3-turbo` 는 오디오 1분당 46.63 뉴런이고
무료 한도가 하루 10,000 뉴런이다. 하루 3.5시간 분량까지 공짜라, 1분짜리 숏츠면 200개까지 무료다.

**모델 응답을 그대로 쓰지 않는다.** Whisper 가 주는 문장은 자막으로 쓰기엔 길 때가 많아서,
단어 단위 시각을 이용해 20자 / 4초 / 문장부호 기준으로 다시 끊는다 (`chunkSegments`).

## 유튜브 숏츠 업로드

내보낸 영상을 다운로드 없이 바로 유튜브에 올립니다. OAuth 는 팝업으로 처리해서
편집 중이던 클립이 날아가지 않습니다. (리디렉션 방식이면 페이지가 새로 뜨면서 작업이 사라집니다)

### 준비 (한 번만)

1. [구글 클라우드 콘솔](https://console.cloud.google.com) 에서 프로젝트 생성
2. **API 및 서비스 → 라이브러리** → `YouTube Data API v3` 사용 설정
3. **OAuth 동의 화면** → 외부(External) → 테스트 사용자에 본인 구글 계정 추가
4. **사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션**
   - 승인된 자바스크립트 원본에 `http://localhost:5179` 와 배포 주소를 등록
   - 클라이언트 보안 비밀번호는 쓰지 않습니다 (브라우저 전용 흐름)
5. 나온 클라이언트 ID 를 [내보내기] 탭에 붙여넣기 → **구글 계정 연결**

클라이언트 ID 는 이 브라우저(localStorage)에만 저장됩니다. OAuth 클라이언트 ID 는
원래 공개되는 값이라 정적 사이트에 있어도 문제되지 않습니다.

### ⚠️ 감사를 통과하기 전까지는 비공개로 잠깁니다

2020년 7월 28일 이후 만든 API 프로젝트로 `videos.insert` 를 쓰면,
**올린 영상이 유튜브 서버에서 비공개로 잠기고 나중에 공개로 바꿀 수도 없습니다.**
채널 주인에게 "미인증 클라이언트로 업로드돼 잠겼다"는 메일이 갑니다.

공개 발행까지 하려면 [YouTube API 규정 준수 감사](https://support.google.com/youtube/contact/yt_api_form)를
신청해야 합니다. 신청서에 **이 앱의 OAuth 흐름 데모 영상**이 필요하므로, 앱이 먼저 있어야 합니다.
감사 전에도 비공개 업로드로 전체 흐름은 확인할 수 있습니다.

## 인스타 릴스

메타 API 는 로컬 파일을 받지 않는다. 공개 URL 을 메타 서버가 직접 받아가는 구조라
브라우저에서 바로 올릴 수 없다. 대신 옆 프로젝트 `instagram-autopost` 에 명령이 붙어 있다.

```bash
python main.py publish-video 내려받은파일.mp4 --caption "캡션"
```

규격 손질(faststart / 무음 AAC 트랙 / H.264 변환) -> GitHub 공개 저장소 업로드 ->
릴스 발행 -> 발행 기록까지 한 번에 간다. 표지도 영상에서 자동으로 뽑는다.

**페이스북 릴스는 아직이다.** 지금 토큰이 Instagram Login 방식(`graph.instagram.com`)이라
페이스북 페이지에 접근할 수 없다. 페이스북 릴스는 페이지 토큰 + Facebook Login 이 따로 필요하다.

## 배포

Cloudflare Pages 에 직접 업로드하는 방식으로 올라가 있다. 빌드 단계가 없으므로 이걸로 충분하다.

```bash
npx wrangler pages deploy public --project-name shorts-studio --branch main
```

프로젝트 이름은 `shorts-studio`, 주소는 https://shorts-studio-75p.pages.dev 다.

### GitHub 에 연결하려면 (선택)

푸시할 때마다 자동 배포되게 하려면 저장소를 만들어 연결한다.

```bash
git remote add origin https://github.com/xixili0124-star/shorts-studio.git
git push -u origin main
```

그다음 Cloudflare 대시보드 > Workers & Pages > shorts-studio > Settings > Builds 에서
Git 저장소를 연결하고, Build command 는 비우고 Output directory 를 `public` 으로 둔다.

**주의**: Git 연결로 바꾸면 위의 직접 업로드(`wrangler pages deploy`)와 섞어 쓰지 않는 게 좋다.
둘을 번갈아 쓰면 어느 쪽이 마지막 배포인지 헷갈린다.

### 유튜브 OAuth 원본 등록

배포 주소가 생겼으므로 구글 클라우드 콘솔의 OAuth 클라이언트 설정에서
**승인된 자바스크립트 원본**에 `https://shorts-studio-75p.pages.dev` 를 추가해야
배포된 사이트에서도 유튜브 업로드가 된다. (로컬 주소와 둘 다 등록해두면 된다)

## 알아둘 점

- 60초가 넘으면 경고가 뜹니다. 숏츠·릴스는 60초 이하가 안전합니다.
- 긴 영상은 메모리를 많이 씁니다. 완성본이 100MB를 넘길 정도면 나눠서 만드는 편이 낫습니다.
- 아이폰 HEVC(H.265)는 윈도우에 "HEVC 비디오 확장" 이 있어야 디코딩됩니다. 없으면 H.264 MP4 로 변환 후 올려주세요.
- 파일 용량 자체는 보통 문제가 되지 않습니다(통째로 읽지 않음). 다만 수 GB + 인덱스가 파일 끝에 있는 조합이면
  브라우저가 메타데이터를 찾느라 오래 걸릴 수 있어, 45초를 넘기면 디코더 모드로 넘어갑니다.
- 저작권 있는 음원을 넣으면 업로드한 플랫폼에서 음소거되거나 제한될 수 있습니다.

## 파일 구조

```
stt-worker/                  자동 자막 서버 (Cloudflare Worker)
  src/index.js
  wrangler.jsonc
public/
  index.html
  style.css
  vendor/mediabunny.min.js   인코딩·디코딩 엔진 (MPL-2.0)
  js/
    main.js        UI 연결
    state.js       프로젝트 상태 + 타임라인 계산
    render.js      프레임 렌더러 (미리보기·내보내기 공용)
    player.js      미리보기 재생
    exporter.js    내보내기 (WebCodecs / MediaRecorder 폴백)
    audio.js       오디오 믹싱
    media.js       파일 → 클립
    youtube.js     유튜브 업로드 (OAuth + 재개 가능 업로드)
    srt.js         자막 파일 입출력
    transcribe.js  자동 자막 (워커 호출 + WAV 인코딩)
    util.js
```
