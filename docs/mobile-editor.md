# 모바일 편집 화면

모바일은 전용 작업 화면을 사용합니다. PC 화면을 좁히는 대신 미리보기, 한 트랙 편집, 현재 작업 도구를 중심으로 배치하되 편집 데이터와 실행 엔진은 PC와 공유합니다.

## 화면

- 기본 자동 선택: 폭 760px 이하, 또는 터치 중심 기기의 폭 1100px 이하.
- `#mobileStudioShell`에 프로젝트 메뉴·완성 버튼, 미리보기, 타임라인, 하단 작업 도구를 배치합니다.
- 세로: 프로젝트 헤더 → 미리보기 → 트랙 선택과 타임라인 → 현재 작업 도구.
- 가로: 미리보기와 타임라인을 좌우로 배치합니다.
- 라이브러리·속성·메뉴는 공통 작업 패널에서 열립니다. 완료 버튼으로 편집 화면에 돌아갑니다.
- 아무 클립도 선택하지 않으면 추가·자막·소리·그래픽·퀵포맷을 보여줍니다. 선택하면 문구·글꼴, 분할·화면, 음량 등 해당 항목의 편집 도구로 바뀝니다.
- 속성은 선택한 작업에 필요한 구간만 보여줍니다. 예를 들어 글꼴에서는 글자 스타일, 음량에서는 볼륨과 음소거만 표시합니다. 전체 속성은 클립 메뉴의 세부 편집에서 엽니다.
- PC의 저장된 타임라인 높이를 모바일 배치로 덮어쓰지 않습니다.
- 검수 주소 옵션 `?ui=mobile` / `?ui=desktop`은 화면에만 적용하며 저장하지 않습니다.

## 트랙 집중 보기

- 기본은 영상 한 트랙을 크게 보여주는 집중 보기입니다. PC의 왼쪽 트랙 헤더를 접고 타임라인의 가로 공간을 사용합니다.
- 트랙 이름 칩을 눌러 영상·자막·그래픽·오디오·보이스 등 작업할 행을 바꿉니다. 빈 트랙도 선택할 수 있습니다.
- 전체 트랙 버튼을 누르면 모든 행과 트랙 배지를 함께 표시합니다. 다시 누르면 한 트랙씩 보는 화면으로 돌아옵니다.
- `timeline.setMobileTrackView({all, trackId})`는 표시 속성만 갱신합니다. `.track`과 `.track-head`의 `data-mobile-visible`, 타임라인 패널의 `data-mobile-track-view`를 CSS가 읽습니다.
- 표시 필터는 트랙의 `hidden`·`muted` 설정이나 클립을 수정하지 않습니다. 미리보기·내보내기에서 다른 트랙이 빠지는 기능이 아닙니다.
- 재렌더 후에도 집중 보기를 유지합니다. 선택한 트랙이 없어지면 사용 가능한 영상 트랙, 또는 첫 트랙으로 돌아갑니다. 가려진 행은 포인터·메뉴·드롭·영역 선택 대상으로 사용하지 않습니다.
- `timeline.restoreMobileTrackView()`는 모바일 표시 상태와 속성을 제거합니다. 같은 상태의 반복 동기화는 행 DOM을 다시 만들지 않으며, 전체 보기에서 다른 행을 선택해도 진행 중 이동을 취소하지 않습니다.

## 타임라인 조작

- 탭: 클립·공백·전환 선택. 빈 배경 또는 눈금을 탭하면 재생 위치 이동.
- 쓸기: 가로·세로 스크롤.
- 클립을 300ms 길게 누르고 이동: 기존 이동·교환·연결 클립 편집 사용.
- 길게 누르고 제자리에서 놓기: 클립 메뉴.
- 선택 클립 양끝 손잡이: 길이 조절.
- 두 손가락: 손가락 중점의 시각을 유지하며 확대·축소. 진행 중 이동은 취소.
- 클립 메뉴의 ‘여러 클립 선택’: 탭으로 선택 추가·해제. 분할·삭제·설정 붙여넣기는 기존 묶음 명령을 사용.
- 클립 상단 설정 버튼은 모바일에서 숨깁니다. 복제·설정 복사 및 붙여넣기·삭제 등은 클립 메뉴에서 실행합니다.
- 프로젝트 메뉴: 저장·열기·트랙 관리·스냅·반복 재생·안전영역·도움말. 실행 취소·다시 실행과 확대·축소는 타임라인 가까이에 둡니다.

## PC와 공유하는 DOM

`mobile-studio.js`는 기존 미리보기·타임라인·라이브러리·속성 노드를 모바일 호스트로 이동합니다. 별도의 편집기 인스턴스나 두 번째 타임라인을 만들지 않습니다. 작업 패널을 닫으면 라이브러리와 속성은 숨겨진 보관 영역으로 옮기고, PC 모드로 복귀하면 미리 기록한 원래 DOM 위치에 돌려놓습니다.

모드 변경 때 터치 제스처를 정리하고 다중선택 모드를 해제합니다. 기존 이벤트 리스너·선택 데이터·재생 상태는 같은 노드와 편집 엔진을 사용합니다. PC 복귀 시 모바일 속성 필터도 제거합니다.

## 경계

`mobile-studio.js`는 기존 앱 명령에 연결하는 화면 제어기입니다. 렌더러, 인코더, 프로젝트 형식, 자동자막/TTS/추적의 엔진 선택·동의·다운로드 정책을 복제하거나 변경하지 않습니다. 모바일 화면을 열었다고 PC 전용 엔진이 휴대전화에서 실행되는 것은 아닙니다.

`mobile.css`의 편집 화면 규칙은 `body.mobile-ui` 안에 적용하며, PC에서는 전용 모바일 셸을 숨깁니다. 기존 PC 마우스 타임라인 동작을 유지합니다. 모바일의 명시적 다중선택 모드는 연결된 마우스나 펜으로도 같은 선택 동작을 제공합니다.

## 검증

Node 검사: `tests/mobile-studio.test.mjs`, `tests/mobile-timeline-touch.test.mjs` 및 기존 전체 검사. 트랙 표시와 문서 숨김 상태의 분리, 재렌더·PC 복귀, 사라진 트랙 대체, 가려진 행의 입력 차단을 포함합니다.

2026-09-06 재설계 코드 기준으로 Node 14개 검사 파일의 382개 테스트가 모두 통과했습니다. Canvas 검사를 포함하며 실패·건너뛴 테스트는 없습니다. `public/js` 문법 검사 오류와 원본 작업 폴더 해시 변경도 없었습니다.

`tests/browser-mobile.html`을 로컬 정적 서버의 공개 디렉터리에 임시 복사하여 11개 검사를 실행할 수 있습니다. 독립 `#mobileEditDeck`에서 실제 제품 CSS·Timeline DOM·좌표 판정·이동/트림 명령을 사용합니다. 탭, 스크롤, 길게 누르기, 이동, 트림, 핀치, 다중선택, 취소와 함께 집중/전체 보기의 실제 행 크기·표시·hit-test·복원을 확인합니다. 사용자 프로젝트나 자동 저장은 불러오지 않습니다. 검사 후 공개 디렉터리의 복사본은 제거합니다.

2026-09-06 브라우저에서 위 11개 검사가 모두 통과했습니다. 포인터 이벤트와 캡처는 테스트용으로 모사하므로, 이 검사와 화면 크기 검사는 실제 휴대전화의 조작 검증을 대체하지 않습니다.

실제 휴대전화에서 별도 확인할 항목: iOS Safari/Android Chrome의 터치 캡처, 주소창·가상 키보드·회전, 파일 선택, 내보내기/다운로드, 기기별 메모리 한계. 데스크톱의 모바일 화면 크기 검사와 실제 기기 검증은 구분합니다.
