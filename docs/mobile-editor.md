# 모바일 편집 화면

모바일은 미리보기, 모든 트랙, 현재 작업 도구를 중심으로 배치합니다. 편집 데이터와 실행 엔진은 PC와 공유하며 PC 화면을 변경하지 않습니다.

## 화면

- 기본 자동 선택: 폭 760px 이하, 또는 터치 중심 기기의 폭 1100px 이하. `?ui=mobile` / `?ui=desktop`은 검수용 화면 선택이며 저장하지 않습니다.
- 프로젝트 헤더 → 미리보기 → 전체 타임라인 → 현재 작업 도구 순서입니다. 가로 화면은 미리보기와 타임라인을 좌우로 둡니다.
- 한 트랙 집중 보기와 전체/집중 전환 버튼, 트랙 이름·개수를 나열한 요약 줄은 제거했습니다.
- 기본 자막·그래픽·영상·오디오·보이스 다섯 트랙을 모두 보여줍니다. 왼쪽에 실제 트랙 이름을 표시하며 트랙 관리 버튼은 타임라인 제목 옆에 있습니다.
- 세로 화면의 타임라인 작업대는 328px, 기본 행은 48px입니다. 높이 700px 이하에서는 314px / 46px로 조정합니다. 가로 화면은 창 높이에 맞춰 행 높이를 조정합니다. 가로 스크롤바까지 고려해 마지막 보이스 행이 가려지지 않도록 했습니다.
- 추가한 트랙은 타임라인 안에서 세로로 스크롤합니다. 모든 행을 표시하는 것은 문서의 화면 숨김·음소거 설정과 별개입니다.
- 선택 전 하단 도구는 추가·자막·소리·그래픽·퀵포맷입니다. 같은 폭의 다섯 칸에 구분선을 두고 아이콘과 문구를 중앙 정렬합니다. 선택 후에는 같은 위치에 선택 항목의 편집 도구가 나옵니다.
- PC에 저장한 패널 폭·타임라인 높이는 모바일 배치로 덮어쓰지 않습니다.

## 타임라인 터치

- 한 손가락 드래그: 재생 위치를 옮깁니다. 선택이나 타임라인 스크롤은 바꾸지 않습니다.
- 터치 시작 후 120ms 동안 두 번째 손가락을 기다려 한 손가락 편집이 먼저 실행되는 실수를 줄입니다. 120ms보다 짧은 드래그는 놓는 시점에 재생 위치만 갱신합니다.
- 탭: 클립·공백·전환을 선택합니다. 빈 배경이나 눈금을 탭하면 재생 위치를 옮깁니다.
- 선택하지 않은 클립의 끝을 건드려도 트림하지 않습니다. 먼저 탭으로 선택한 뒤, 다음 터치에서 양끝 손잡이를 끌어 길이를 조절합니다. 미선택 손잡이는 보이지 않고 포인터 입력도 받지 않습니다.
- 선택한 클립 본문을 300ms 누른 뒤 끌면 기존 이동·교환 기능을 사용합니다. 바로 끌면 재생 위치만 옮깁니다. 길게 누르고 제자리에서 놓으면 클립 메뉴를 엽니다.
- 두 손가락: 가로·세로 스크롤과 핀치 확대·축소를 함께 처리하며 손가락 중점의 시각을 유지합니다.
- 클립 편집 중 두 번째 손가락이 닿으면 미확정 편집을 취소하고 두 손가락 조작으로 전환합니다. 한 손가락만 남아도 재생 위치나 클립 편집을 다시 시작하지 않으며, 모두 뗀 뒤 새 터치에서 시작합니다.
- 포인터 취소·창 포커스 이탈·화면 전환 시 편집을 확정하지 않고 정리합니다. PC 마우스·펜의 기존 동작은 유지합니다.
- ‘여러 클립 선택’은 탭으로 선택을 추가·해제합니다. 분할·삭제·설정 복사·붙여넣기는 기존 묶음 명령을 사용합니다.

## PC에서 이어받은 사용 흐름

- 완성 버튼을 내보내기로 통일했습니다.
- 자막 화면은 현재 위치 자막 추가를 스타일 목록 위에 둡니다. 자동 자막은 별도 화면이며 직접 추가나 스타일 선택을 섞지 않습니다.
- 소리 메뉴에 AI TTS와 무음 컷을 두고 해당 화면에서 소리 메뉴로 돌아갈 수 있습니다.
- 영상 클립 더보기에서 모자이크 트래킹과 크롭 트래킹 화면으로 들어갑니다.
- 파일 삭제·추가, 분류된 효과음, 내 목소리 목록, 저장 퀵포맷, 선택 속성 슬라이더는 PC와 같은 구현을 사용합니다.
- 기존 모델 선택·처리 위치·동의·다운로드 정책은 유지합니다. PC 전용 엔진을 휴대전화에서 실행하는 것으로 바꾸지 않습니다.

## 구현과 보존

`mobile-studio.js`는 미리보기·타임라인·라이브러리·속성의 기존 DOM을 모바일 호스트에 옮기는 화면 제어기입니다. 별도 프로젝트나 렌더러를 만들지 않습니다. PC 복귀 시 원래 DOM 위치와 속성 필터를 복원합니다.

`timeline.setMobileTrackView()`는 구형 `all:false` 입력도 모든 트랙 표시로 정규화합니다. 트랙 선택은 추가 대상만 바꾸며 다른 행을 숨기거나 문서를 수정하지 않습니다. 재렌더 중에도 같은 전체 보기 상태는 진행 중인 드래그를 취소하지 않습니다.

`mobile.css`의 제품 화면 규칙은 `body.mobile-ui`에만 적용됩니다. 새 의존성, 빌드 단계, 서버 전송 또는 AI 엔진 변경은 없습니다.

## 검증

2026-09-06: Node 전체 422개 검사 통과, 모든 JS 문법 검사 통과. 기존 별도 작업 폴더의 변경이 없음을 확인했습니다.

모바일 브라우저 통합 14개와 PC 통합 15개가 통과했습니다. 390×844·360×740 기본 다섯 행, 균등 도구 칸과 메뉴 연결을 자동 검사했습니다. 실제 미리보기에서도 375×667·844×390·390×844 창을 확인했으며 기본 다섯 행의 세로 스크롤 초과는 모두 0px였습니다. 세로 390px 설정의 하단 버튼 폭 차이는 0.02px 이내였고 전환 아이콘은 트랙 중앙에 배치됐습니다.

`tests/browser-mobile.html`은 독립 Timeline 프로젝트의 합성 PointerEvent 검사와 빈 편집기 iframe의 실제 DOM 배치·메뉴 검사를 제공합니다. 공개 디렉터리 `public/_test/`에 임시 복사하여 별도 검수 포트에서 실행합니다. 사용자 프로젝트 대신 테스트 파일과 빈 상태를 사용하며 AI 처리·모델 다운로드·영상 인코딩은 실행하지 않습니다.

실제 휴대전화의 iOS Safari/Android Chrome 터치 하드웨어, 포인터 캡처, 주소창·키보드·화면 회전과 성능은 별도 검증 대상입니다. 데스크톱 브라우저의 화면 크기 검사와 합성 터치 검사를 실기 검증으로 간주하지 않습니다.
